## Relationship to This Repo

**Update (2026-07-31): the Planet table is now wired in, as a display
layer only.** `standalone_rca_sandbox.py`'s `SEPHIRAH_PLANET_COLOR` dict
maps the 7 sephirot this codex's Planet table gives a classical planet to
(Tifereth/Sun, Yesod/Moon, Hod/Mercury, Netzach/Venus, Geburah/Mars,
Chesed/Jupiter, Binah/Saturn) onto this table's Queen-scale hex colors,
and `colorize_sephirah()`/`sephirah_planet_label()` use that mapping to
color the already-existing `dominant_seph` output from `/eval` and the
main interaction pipeline. This does **not** re-classify or refine
anything — it decorates an existing, already-tested classification with
a color, per the three options weighed before building it (see
`LIBER_0.md`'s entry on this feature for the other two options and why
they were not chosen). Keter, Chokmah, Daath, and Malkuth have no
planetary color in this table and remain uncolored in the code, on
purpose — see `SEPHIRAH_PLANET_COLOR`'s own comment in
`standalone_rca_sandbox.py`. Covered by 7 new tests in
`test_standalone_rca_sandbox.py` (`TestSephirahColorDisplay`), including
one that cross-checks the code's hardcoded hex values directly against
this document's text so the two can't silently drift apart.

**Note on spelling**: this repo's code spells the sixth sephirah
`"Tifereth"` throughout; this document (as uploaded) transliterates it
`"Tiphareth"`. Both are standard transliterations of the same Hebrew word
(תפארת) — not a corruption, just a spelling variance across two documents
with different origins. The code follows its own existing spelling so it
actually matches the classification output it colors.

**Update (2026-07-31): the 100-emotion codex now has a data-fidelity
layer, but emotion detection itself remains deliberately unwired.**
[`../glyph_emotion_codex.py`](../glyph_emotion_codex.py)
parses this table directly from this document (rather than maintaining
a separate hand-copied literal that could silently drift), and
[`../glyph_emotion_correspondence_ledger.py`](../glyph_emotion_correspondence_ledger.py)
registers exactly one VERIFIED claim on top of it — that the code's view
of the table matches this document's literal text (11 tests in
`test_glyph_emotion_codex.py`, including hand-checked spot values). That
is display/reference-layer work only, the same kind of thing the
Planet-table color layer above already does; it makes no claim about
detecting emotions from anything.

The keyword-classifier claim (detecting which emotion a piece of text
expresses by keyword matching) remains exactly what it was: it would
require inventing ~100 new keyword lists with no independent ground
truth to check them against, and stays registered as an explicit
UNTESTABLE row in the ledger.

**Update (2026-08-01): the qualia-vector-to-emotion mapping is now
wired, without inventing a per-emotion signature.**
[`../qualia_emotion_classifier.py`](../qualia_emotion_classifier.py)
closes this gap in two stages, using only data that already existed:
it buckets the 100 emotions by the covered sephirah their own Esoteric
column already names, computes each covered sephirah's reference qualia
signature by running its existing `SEPHIROT_CENTROIDS` words through the
same tested scoring pipeline, routes an input to its nearest reference
by Euclidean distance, and within that bucket picks the emotion whose
own existing gradient hex (converted to HSL lightness) is closest to the
input's `Tau_resonance`. Chesed is excluded from Stage 1 entirely — a
direct grep confirms "Jupiter" never appears in this table's Esoteric
column, so Chesed has zero emotions to route into — and Madness (#90,
Uranus) and Chaos (#91, Spirit) stay explicitly uncovered, same
treatment as the 4 uncolored sephirot above. See
`docs/qualia_emotion_classifier_hand_verification.md` for the full
derivation, including a discovered limitation (Geburah's and Chesed's
reference signatures collide exactly, because `Delta_gamma`'s absolute
value discards which side an imbalance is on) documented rather than
hidden. `glyph_emotion_correspondence_ledger.py`'s entry for this claim
is now VERIFIED (35 tests in `test_qualia_emotion_classifier.py`) — for
the ALGORITHM running as described, not for any emotion "truly"
belonging to any sephirah or hex value, which remains Register A exactly
as before (see `docs/fixed_point_closure_and_the_y_combinator.md` §1).
